================================================================================
                    SEGURANÇA DE SENHAS: BCRYPT + SALT + PEPPER
================================================================================

1. ARQUITETURA DE SEGURANÇA
O ZTFramework adota a camada tripla de proteção recomendada pelo OWASP:

[ Senha em Texto Plano ]
          |
          v
[ HMAC-SHA256 com Pepper Secreto ] -> Normaliza a senha para 64 chars hexadecimais,
          |                           eliminando o limite nativo de 72 bytes do BCrypt.
          v
[ BCrypt + Salt Criptográfico ]    -> Aplica Blowfish adaptativo com cost configurável
          |                           e Salt aleatório único por registro.
          v
[ Hash Final (60 caracteres) ]     -> Gravado no banco de dados.

2. O PAPEL DO PEPPER
O Pepper é uma chave secreta estática configurada em `app/etc/config.json`:
`"security": { "password_pepper": "...", "bcrypt_cost": 12 }`

VANTAGEM CRÍTICA:
Se o banco de dados for comprometido ou vazado em um dump SQL, o atacante NÃO conseguirá
quebrar os hashes por Rainbow Tables ou ataques de dicionário, porque o Pepper secreto
NÃO reside no banco de dados!

3. CLASSE app\core\utils\PasswordSecurity
- PasswordSecurity::hash(string $password): string
  * Aplica HMAC-SHA256 com o Pepper e gera o hash BCrypt com o Salt interno.
- PasswordSecurity::verify(string $password, string $storedHash): bool
  * Aplica o Pepper na senha digitada e valida contra o hash armazenado.
- PasswordSecurity::needsRehash(string $storedHash): bool
  * Verifica se o fator de custo (cost) foi aumentado no config.json para atualizar
    o hash do usuário de forma transparente no próximo login.
